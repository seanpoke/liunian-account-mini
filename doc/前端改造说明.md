# 流年小账 · 小程序前端改造说明

> 面向：负责小程序前端的 AI / 开发者
> 对应后端版本：2026-10-20（家庭共享 + 邀请审批重构 + 图片走 CDN）
> 权威契约：同目录 `接口文档.md`（每个接口的请求/响应/错误码以它为准，本文只说明「改哪里、怎么改」）

---

## 0. 一句话背景

后端已把「成员状态 + 邀请已使用标记」重构为 **`invitation`(1) + `join_request`(N)**：一条邀请可被多人使用、申请单独立留痕；成员退出改为物理删除并作废其流水；新增多家庭、用户资料、图片上传（CDN 直出）、隐私授权、预算、提醒、小程序码等能力。**旧前端的成员审批、邀请、家庭切换、图片地址拼接相关代码基本都要改。**

## 1. 全局约定（所有请求都要先对齐）

| 项 | 值 |
|---|---|
| Base URL | `http://<host>:8445/api`（本地）/ `https://<域名>/api`（线上），**必须带 `/api` 前缀** |
| 鉴权 | 请求头 `Authorization: Bearer <token>`，`token` 来自 `POST /login` |
| 响应结构 | `{ code, msg, data }`，`code === 0` 才算成功，其余弹 `msg` |
| 金额 | 全部是**整数分**（`3500` = ¥35.00）；展示 `/100`，提交 `Math.round(元 * 100)` |
| 日期 | `yyyy-MM-dd`；提醒时间 `HH:mm`；时间戳字段是 ISO 本地时间（如 `2026-10-20T09:15:00`） |
| ID | `familyId` / `memberId` / `categoryId` / `id` **全部是 JSON number**，旧的字符串分类字面量（`g_exp_food` 之类）已废弃 |
| 空值陷阱 | 未加入家庭时 `login.familyId === ""`；账目无分类时 `categoryId === ""`。判断必须写 `familyId !== '' && familyId != null` |

### 错误码处理（建议在 request 封装里统一处理）

| code | 前端行为 |
|---|---|
| 400 | Toast `msg`（参数错误 / 资源不存在） |
| 401 | 清 token → `wx.login` 静默重新登录 → 重放一次原请求；仍失败才跳登录页 |
| 403 | Toast `msg`（非家庭成员 / 仅创建者可操作） |
| 409 | Toast `msg`（重复操作 / 家庭人数已达上限 10 人） |
| 410 | 邀请失效专用：跳「邀请已失效」页，不要当普通错误弹 Toast |
| 500 | Toast「服务繁忙，请稍后重试」 |

## 2. 破坏性变更清单（老代码必须改，否则必挂）

| # | 变更点 | 旧写法 ❌ | 新写法 ✅ |
|---|---|---|---|
| 1 | 成员审批列表改名 | `GET /family/{id}/pending` | `GET /family/{id}/join-requests` |
| 2 | 审批接口改名 + 改参 | `POST /family/{id}/member/{mid}/approve` | `POST /family/{id}/join-request/{requestId}/approve` / `.../reject`（body 可选 `{remark}`） |
| 3 | 成员表不再有状态 | 成员列表读 `status` / `source`，区分「待通过」 | 只返回真实成员：`memberId, openid, nickname, avatar, role, joinedAt, monthCount`；退出/被移除的人直接消失 |
| 4 | 邀请不再一次性 | 判断 `used`、申请后邀请失效 | 邀请**未过期即可复用（1:N）**，无 `used` 字段；失效直接 `410` |
| 5 | 申请状态由申请单决定 | 读成员状态判断「已申请」 | `GET /invitation/{token}` 返回 `applied` + `applicationStatus`（`none/pending/approved/rejected`） |
| 6 | 多家庭 | 全局只存一个 `familyId` | `GET /families` 返回数组；**所有业务接口都要传 `familyId`**；需新增「选择家庭」入口 |
| 7 | 分类 ID 数字化 | `categoryId: "g_exp_food"` | `categoryId: 12`（number）；自定义分类 `code` 可空 |
| 8 | 退出语义变了 | 退出后历史仍在 | 退出/被移除 → 本人该家庭流水**作废**（保留但不展示、不计统计）；仅剩自己 → 整户解散 |
| 9 | 创建者可直接退出 | 必须先转让 | 可直接退出，系统自动把最早加入的成员升为 owner |
| 10 | **图片地址改为绝对 URL** | 后端返回 `/api/files/...`，前端拼域名 | 后端返回 `https://images.sean.ltd/2026/10/xxx.jpg`，**前端原样使用，禁止再拼 BASE**（详见第 5 节） |
| 11 | 新增资料/隐私/预算/提醒 | 可能没有 | `GET/PATCH /user/me`、`GET/POST /user/privacy`、`GET/PUT /budget`、`GET/PUT /reminder` |

## 3. 接口清单（可直接照着写 `api.js`）

### 3.1 登录 / 用户

| 方法 | 路径 | 鉴权 | 关键字段 |
|---|---|---|---|
| POST | `/login` | 否 | 入：`code`（+ 可选 `nickname/avatar/unionid`）；出：`token, openid, isMember, familyId, privacyAgreed` |
| GET | `/health` | 否 | 探活，可选 |
| GET | `/user/me` | 是 | 出：`openid, nickname, avatar, privacyAgreed` |
| PATCH | `/user/me` | 是 | 入：`nickname?, avatar?`；**全局生效，会同步刷新该用户所有家庭的成员昵称** |
| GET | `/user/privacy` | 是 | 出：`agreed, agreedAt` |
| POST | `/user/privacy` | 是 | 入：`{ agreed: true }`；`false` 不写库、不撤销 |
| POST | `/upload` | 是 | multipart：`file`（≤5MB，jpg/png/webp/heic）+ 可选 `familyId`；出：`key, url, fullUrl, size, contentType` |

### 3.2 邀请 / 加入申请

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/invitation` | 是（owner） | 入：`familyId, type('share' 默认 / 'qr')`；出：`token, type, expireAt, reused, qrImageUrl`；满 10 人 → 409 |
| GET | `/invitation/{token}` | 建议带 token | 不带也能看，但 `applied/applicationStatus` 会退化为 `false/none`；失效 → 410 |
| POST | `/invitation/{token}/apply` | 是 | 入：`nickname?, avatar?`；出：`{ status: 'pending' }`；已在该家庭 → 409；邀请失效 → 410 |
| POST | `/invitation/revoke` | 是（owner） | 入：`{ token }`；撤销后该邀请的 pending 申请自动过期 |
| GET | `/family/{familyId}/join-requests` | 是（owner） | 出：`[{ requestId, nickname, avatar, applicantOpenid, applyAt, channel }]`，仅 pending，按申请时间升序 |
| POST | `/family/{familyId}/join-request/{requestId}/approve` | 是（owner） | 已处理 → 400；满员 → 409 |
| POST | `/family/{familyId}/join-request/{requestId}/reject` | 是（owner） | body 可选 `{ remark }`；被拒后可凭有效邀请重新申请 |
| GET | `/wxacode?familyId=` | 是（owner） | 出：`{ qrImageUrl }`，等价 `type=qr` 的邀请 |

**邀请落地页三态分流：**

```js
const { applied, applicationStatus } = data; // applicationStatus 恒为非空字符串
if (applicationStatus === 'approved') {
  // 已是成员 → 写入当前 familyId → switchTab 首页
} else if (applicationStatus === 'pending') {
  // 等待审批页（轮询 GET /invitation/{token} 或 GET /families）
} else {
  // 'none' | 'rejected' → 邀请确认页（家庭名/邀请人/有效期 + 「加入」按钮 → apply）
}
```

### 3.3 家庭 / 成员

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/families` | 是 | `[{ familyId, role, memberCount, name, currency, avatar }]`，多家庭选择页数据源 |
| POST | `/family` | 是 | 入：`{ name }`；出：`{ familyId }` |
| GET | `/family/{familyId}` | 是 | `id, name, creatorOpenid, currency, avatar, memberCount, status` |
| PATCH | `/family/{familyId}` | owner | `name? / currency? / avatar?` |
| POST | `/family/{familyId}/dissolve` | owner | **物理删除整户**（账单/邀请/申请/自定义分类/预算/提醒），不可恢复 |
| GET | `/family/{familyId}/members` | 是 | `memberId, openid, nickname, avatar, role(owner/member), joinedAt, monthCount` |
| DELETE | `/family/{familyId}/member/{memberId}` | owner | 物理移除 + 其流水作废；创建者不可移除（403） |
| POST | `/family/{familyId}/transfer` | owner | 入：`{ toOpenid }` |
| POST | `/family/{familyId}/quit` | 是 | 三种结果：仅剩本人→解散 / 普通成员→流水作废+删成员 / owner→同上并自动转让 |
| PATCH | `/family/{familyId}/member/me` | 是 | 仅改**该家庭内**的昵称头像（与全局 `PATCH /user/me` 区分） |

### 3.4 分类 / 记账 / 统计

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/categories?familyId=&type=expense\|income` | 系统预置 + 本家庭自定义的并集，按 `sort` 升序；字段 `id, familyId(null=系统), name, type, code, icon(emoji), color, sort, isSystem` |
| POST | `/category` | 入：`familyId, name, type` + 可选 `code/icon/color`；`code` 建议不填（全局唯一，格式 `^[a-z][a-z0-9_]{1,31}$`） |
| DELETE | `/category/{id}` | 仅自定义可删，系统分类 → 403 |
| POST | `/transaction` | 入：`familyId, type, amount(分, >0), categoryId(可选), date(yyyy-MM-dd), note?, images?[]`；出：`{ id }` |
| PUT | `/transaction/{id}` | 同字段可选；owner 可改他人，member 仅自己 |
| DELETE | `/transaction/{id}` | 物理删除 |
| GET | `/transaction/{id}` | `id, familyId, openid, nickname, type, amount, categoryId, categoryName, categoryIcon, categoryColor, date, note, images[], createdAt, updatedAt` |
| GET | `/transactions?familyId&start&end&member(openid)&type&category(Long)&page&size` | 出：`{ list, total }`，只含有效流水 |
| GET | `/transactions/by-day?familyId&start&end` | 首页时间线：`{ days:[{date, income, expense, balance, list[]}], total }`，**天按日期降序** |
| GET | `/stats?familyId&period=month\|year\|custom&month=9&year=2026&start&end&member` | 出：`income, expense, balance, byCategory[], byDay[], byMember[]` |

> ⚠️ `month` 传**数字 9**，不能传 `"2026-09"`（后端直接 400）。`period=custom` 必须同时给 `start/end`。

### 3.5 预算 / 提醒

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/budget?familyId=` | 出：`{ amount }`（分，未设置 = 0） |
| PUT | `/budget` | 入：`{ familyId, amount(分, ≥0) }`，**仅 owner**（403 提示） |
| GET | `/reminder?familyId=` | 出：`{ enabled(1/0), time("20:00" 或 ""), tmplId }` |
| PUT | `/reminder` | 入：`{ familyId, enabled?, time?, tmplId? }`；`time` 必须 `HH:mm`，否则 400 |

## 4. 页面级改造清单

| 页面 / 模块 | 要做什么 |
|---|---|
| **登录 / 启动页** | 读 `login` 的 `isMember` + `privacyAgreed`：未同意隐私 → 隐私弹窗（`POST /user/privacy`）；`isMember=true` → 进首页；否则 → 建家庭 / 邀请落地页 |
| **邀请落地页**（`pages/invite/invite`，小程序码指向此页） | 从 `options.scene` / query 取 `token`；带 Authorization 调 `GET /invitation/{token}`；按 `applicationStatus` 三态分流；410 → 失效页 |
| **等待审批页**（新增） | 「已提交，等待创建者通过」；轮询 `GET /invitation/{token}`（30s，`approved` 后进首页）或提供「刷新」按钮 |
| **选择家庭页**（新增） | `GET /families`：1 个直接进，多个列表选择；选择结果持久化，后续请求都带 `familyId` |
| **首页时间线** | 用 `GET /transactions/by-day`；切换家庭时重拉；作废流水后端已过滤，前端勿缓存 |
| **记账页** | 分类用 `GET /categories?familyId&type`，提交数字 `categoryId`；**图片先压缩再 `POST /upload`，直接存返回的 `url`**（详见第 5 节） |
| **账目详情 / 编辑** | 用 `categoryIcon/categoryColor` 渲染；403 时隐藏编辑按钮；作废记录后端当不存在（400），页面兜底「记录已不存在」 |
| **统计页** | 只用后端 `/stats` 结果；`month` 传数字；支持 `member` 筛选、`period=year/custom` |
| **预算页** | `GET /budget` 回显，非 owner 只读；`PUT` 仅 owner |
| **提醒设置页** | `enabled` 用 0/1；时间选择器输出 `HH:mm`；保存后回显接口返回值 |
| **成员管理页** | 去掉状态标签；`role==='owner'` 显示「创建者」徽标；owner 可见「移除 / 转让 / 审批入口」；移除/退出前二次确认，提示「你本人在该家庭的 N 笔账目将作废」；退出后若只剩自己，提示「家庭将被解散」 |
| **加入申请审批页** | `GET /family/{id}/join-requests`；同意/拒绝后移除该行；409 提示人数已满；空态「暂无待审批申请」 |
| **邀请管理页** | `POST /invitation {type:'qr'}` 拿 `qrImageUrl` 展示/保存相册；显示 `expireAt` 倒计时与 `reused` 提示；提供撤销；**不要做「复制链接」** |
| **我的页面** | `GET /user/me` 展示；改昵称头像用 `PATCH /user/me`；隐私协议入口用 `GET /user/privacy` |
| **家庭设置页** | 改名/头像 `PATCH /family/{id}`；解散 `POST /family/{id}/dissolve`（强确认，明确「不可恢复」） |

## 5. 图片与 CDN（本次重点，必须按此实现）

### 5.1 后端返回什么

`POST /upload` 成功后：

```json
{
  "code": 0, "msg": "",
  "data": {
    "key": "2026/10/f5947797cb4340b4b0b784a0f9736547.png",
    "url": "https://images.sean.ltd/2026/10/f5947797cb4340b4b0b784a0f9736547.png",
    "fullUrl": "https://images.sean.ltd/2026/10/f5947797cb4340b4b0b784a0f9736547.png",
    "size": 183420,
    "contentType": "image/png"
  }
}
```

- 线上（配置了 CDN）：`url` 是**绝对地址**；
- 本地开发（未配置 CDN）：`url` 是 `/api/files/2026/10/xxx.png` 相对路径。

### 5.2 前端必须遵守的规则

1. **`url` 原样存入 `transaction.images`**，不要改写、不要截取、不要拼域名。
2. **渲染时直接用** `<image src="{{item.url}}">`；**禁止** `BASE + url`，否则会得到 `https://your-apihttps://images.sean.ltd/...`。
3. 为了兼容本地开发（相对路径），统一用一个小工具函数兜底：

```js
// utils/img.js
export function imgUrl(u) {
  if (!u) return '';
  return /^https?:\/\//.test(u) ? u : BASE + u; // 只有相对路径才补 BASE
}
```

```html
<image src="{{imgUrl(item.url)}}" mode="aspectFill" />
```

4. `fullUrl` 与 `url` 当前完全相同，**只用 `url` 即可**，无需判断。
5. 历史数据里可能残留 `/api/files/...` 相对路径，`imgUrl()` 已能兜住，不需要额外处理。

### 5.3 上传流程（务必先压缩）

```js
wx.compressImage({
  src: tempFilePath,
  quality: 60,
  compressedWidth: 1280,
  success: ({ tempFilePath: small }) => {
    wx.uploadFile({
      url: BASE + '/api/upload',
      filePath: small,
      name: 'file',
      header: { Authorization: 'Bearer ' + token },
      formData: { familyId: currentFamilyId },
      success: (res) => {
        const body = JSON.parse(res.data); // uploadFile 返回字符串，必须手动 parse
        if (body.code !== 0) return wx.showToast({ title: body.msg, icon: 'none' });
        images.push(body.data.url);        // 绝对地址，直接入库
      }
    });
  }
});
```

要点：

- 压缩后 200–400KB，上传耗时和流量下降 80% 以上；
- `wx.uploadFile` 的 `res.data` 是**字符串**，必须 `JSON.parse`；
- 后端限制 5MB、类型 jpg/jpeg/png/webp/heic，且有 magic bytes 校验，改扩展名会被拒；
- 图片不随账目删除而清理（无需前端处理）。

### 5.4 展示与预览

- `<image>` 直接使用 CDN 地址，不受「downloadFile 合法域名」限制；
- 若使用 `wx.previewImage` / `wx.downloadFile`，需在小程序后台把 `https://images.sean.ltd` 加入 **downloadFile 合法域名**；
- CDN 已开启缓存，列表页建议先用压缩图（可在图片 URL 后追加 CDN 支持的缩放参数，若你的 CDN 已启用图片处理）。

### 5.5 头像（同一套逻辑）

头像与记账图片走完全相同的存储路径，但有三条写入接口：

| 字段 | 接口 | 权限 | 影响范围 |
|---|---|---|---|
| `user.avatar` | `PATCH /user/me` | 本人 | 同步刷新该用户**所有家庭**的成员头像 |
| `family_member.avatar` | `PATCH /family/{familyId}/member/me` | 本人 | 仅该家庭内的显示头像 |
| `family.avatar` | `PATCH /family/{familyId}` | 仅 owner | 家庭头像（`POST /family` 不支持传头像，创建后单独设置） |

规则：

1. `chooseAvatar` 返回的是**临时路径**，必须先 `POST /upload`，拿 `data.url` 再提交；
2. 头像不需要原图，先压到 200×200（`wx.compressImage`），单张 20–30KB；
3. **清空头像**：`PATCH /user/me` 或 `PATCH /family/{id}/member/me` 传 `{ "avatar": "" }`；
   注意 `null`/不传 = 不修改，只有空串才是清空；
4. 昵称不允许置空（空串会被忽略）；
5. 展示同样用 `imgUrl()`，不要拼 BASE。

## 6. 容易踩的坑（务必逐条落实）

1. **`familyId` 是 number，但未加入时是空字符串 `""`**；`categoryId` 无分类时也是 `""`。判断用 `familyId !== '' && familyId != null`。
2. **所有列表类接口都必须传 `familyId`**，漏传 → 400。
3. **`month` 是数字**（1–12），不是 `yyyy-MM` 字符串。
4. **金额永远是分**，不要在后端返回的 `amount` 上再 `*100`。
5. **图片 URL 已是绝对地址**，不要再拼 `BASE`；只在 `url` 以 `/` 开头时才补。
6. **`wx.uploadFile` 返回的是字符串**，必须 `JSON.parse`。
7. **401 必须能自愈**：清 token → `wx.login` → `POST /login` → 重放原请求。
8. **410 与 403 不要混用提示**：410 = 邀请失效，403 = 权限不足。
9. **不要缓存「已退出成员」**：退出是物理删除，缓存会出现幽灵成员。
10. **不要在前端自己算统计**：作废过滤只在后端做。

## 7. 前端自测清单（与后端冒烟用例对齐）

1. 新用户登录 → `isMember=false` → 建家庭 → 首页为空 → 记一笔 → 首页/统计出现该笔
2. 生成二维码邀请 → 另一账号扫码 → 邀请页 → 申请 → 创建者审批通过 → 双方成员列表 = 2 人
3. 同一邀请给第 3 人用 → 仍可申请（1:N）→ 审批通过 → 3 人
4. 同一人重复点「加入」→ 仍返回 `pending`，不产生第二条待审（幂等）
5. 拒绝某申请 → 该账号邀请页显示可重新申请 → 重新申请成功
6. 普通成员退出 → 其流水在首页/统计消失，家庭仍在；其余成员数据不变
7. 创建者退出（还有他人）→ 最早加入者变 `owner`，角色徽标即时更新
8. 最后一人退出 → 家庭消失，`GET /families` 为空
9. 预算：owner 设置 5000 元 → 回显 `500000` 分；member 保存 → 403
10. 提醒：设为 `20:00` → 回显一致；传 `8:00` → 400
11. **上传图片 → 返回 `https://images.sean.ltd/...` → `<image>` 可直接显示（不拼 BASE）**
12. 撤销邀请 → 再扫该码 → 410 失效页
13. token 过期/伪造 → 401 → 自动重新登录并恢复
